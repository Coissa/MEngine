# 渲染器建设路线

本轮聚焦实时渲染。撤销事务和通用编辑器架构调整暂停。第一阶段目标已确定：PBR、IBL、多光源和阴影，并同步建立可扩展的渲染架构。

硬件目标已确定为开发机的 RTX 5070。使用 D3D12、DXC、Shader Model 6.6 和 HLSL 2021 作为基础，不维护旧 Shader Model 兼容路径。默认选择高性能硬件适配器；WARP 仅在测试或显式指定时启用。设备初始化时一次性查询 Shader Model、Wave、描述符堆索引、DXR、Mesh Shader 和增强屏障等能力；后续高级路径按实际能力接入。基础光照、PBR、IBL 和阴影不依赖硬件光追。分辨率、帧率和场景规模尚未设定硬指标，性能以实测为准。

## 当前基础

- 已有 D3D12 RHI、显式提交、帧槽和 Fence，命令录制支持取消。
- 已有场景颜色、深度、运动矢量、TAA、编辑器合成和基础 GPU 视锥剔除。
- 方向光、点光和聚光使用金属度/粗糙度 GGX PBR，法线、自发光与 AO 纹理已接入；天空参与漫反射/镜面 IBL，方向光采用四级 CSM。
- Shader 已迁移为 DXC 编译的 SM6.6/DXIL；设备能力通过 RHI 统一描述。纹理 UAV、Mip/Array 子资源视图与状态已贯通；绑定数组按后续实际需求接入。
- 场景与天空已统一为线性 HDR；TAA 在 HDR 颜色上工作，之后统一曝光、色调映射和 sRGB 输出。
- 当前间接绘制仍逐对象绑定和提交；Cluster 几何不能等同于完整的 GPU 驱动虚拟几何系统。
- 源材质与 Cook 材质已统一（payload v2，兼容 v1）；GPU 上传和资源持有仍存在两套实现。
- 默认场景已启用 IBL、方向光阴影、两个点光和一个聚光，砖块/地砖具有配套法线与打包粗糙度图；Scene 面板可编辑光照并观察各阶段 GPU 毫秒数。

## 设计方向

保持 World 到 RenderFrame 的值快照边界，渲染器不读取 World 或编辑器对象。Renderer 负责渲染流程、持久资源和历史；RHI 负责实际设备资源与命令；提交成功后才提交历史状态。

当前保留单一前向路径，将 PBR、IBL、方向光 CSM 与最多 64 盏局部灯接入现有 Renderer/ScenePass。灯光列表使用纯值快照，不增加专用 Manager 或组件文件；局部灯目前逐像素遍历。以后根据场景与性能选择 Forward+ 或 GBuffer，不同时维护两条尚无需求的路径。

当前以现有固定顺序与显式输入管理资源依赖。后续 Pass 数量与可选分支足够复杂时再引入轻量 RenderGraph，优先只使用图形队列。资源别名、异步 Compute 和多队列调度在有明确收益后加入。无需建立统一 Pass 继承体系。

持久 GPU Scene 管理对象、网格、材质和光源数据。资源采用稳定句柄、统一上传与完成 Fence 后释放；场景切换不应依赖重建整个 Renderer。全局 Shader 管线、场景资源和随分辨率变化的资源分别具有明确寿命。

## 建设顺序与验收

| 阶段 | 工作内容 | 验收结果 |
|---|---|---|
| 0：基础契约（已落地） | 硬件基线、设备能力描述、DXC/SM6.6、Mip/Array 子资源视图与状态、纹理 UAV、按帧槽的 GPU 时间查询 | 现有场景、取消录制、Resize、TAA 历史与编辑器合成继续正确工作；能读取各渲染阶段 GPU 耗时 |
| 1：材质与 HDR（本轮已完成） | 统一源/Cook/运行时材质；按纹理槽区分 sRGB 与线性；导数切线法线映射；GGX 金属度/粗糙度、遮罩、自发光与 AO；统一天空与场景的线性 HDR 和 HDR TAA，显示编码放在输出边界 | 材质球阵列、法线贴图和透明裁剪场景正确；源资产与 Cook 资产表现一致；曝光同时正确影响场景和天空 |
| 2：环境光（已落地） | GPU 环境预处理、漫反射环境光、粗糙度相关镜面预过滤、BRDF LUT | 金属和粗糙度变化能正确反映环境；环境旋转与能量变化一致 |
| 3：光照与阴影（基础已落地） | 方向光、点光、聚光；统一光源数据；四级方向光阴影、PCF、稳定投影与级联混合；材质与阴影使用一致的透明裁剪。局部光阴影后续扩展 | 多光源、接收体遮蔽及透明裁剪阴影已验证；继续按实际场景改进投影范围与稳定性 |
| 4：渲染调度 | 用轻量 RenderGraph 接入深度、GBuffer/主光照、阴影、天空、后处理和最终合成；按需建立灯光 Tile/Cluster | Pass 开关和窗口尺寸变化不会破坏资源依赖；可查看 GBuffer、光源分布、阴影和各 Pass 输出 |
| 5：时域与屏幕空间 | 在统一 HDR/曝光契约上改进 TAA；保留上一帧深度、处理历史拒绝；加入 AO、SSR、Bloom、自动曝光与颜色分级 | 相机切换、物体运动、遮挡显露和曝光变化下历史稳定；效果有独立开关与对照场景 |
| 6：规模化 | GPU Scene 增量更新、Hi-Z、遮挡剔除、实例批处理、多绘制间接提交；随后推进 Cluster/LOD | 场景规模增加时能测量 CPU 提交与 GPU 可见性处理的收益；可见性和 LOD 有专用调试视图 |
| 7：扩展能力 | 完善透明、粒子、蒙皮与对应运动矢量；按需求增加体积光、GI、DXR 和 Mesh Shader 路径 | 结合目标硬件选择实际能力，并保持基础路径可独立运行 |

表中的阶段 4、6 是后续规模化方向，目前不为其预建空框架。Mesh Shader、DXR 和异步 Compute 分别按能力和性能需求接入，不作为所有效果的共同前提。

## 第一阶段的完成定义

第一阶段完成阶段 0 到 3 的核心内容：同一场景中能同时展示 PBR 材质、环境光、多光源和阴影；具备统一线性 HDR 流程、基础资源调度和逐 Pass 性能观测。用材质球、室内多光源和户外阴影三类固定场景验收。

每增加一种资源使用方式或渲染 feature，补充对应的行为验证和图像对照。检查放在构建、资源导入和设备初始化边界，正常绘制路径保持明确契约，避免重复校验。
